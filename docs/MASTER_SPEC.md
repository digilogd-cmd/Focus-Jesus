## 0. 최상위 지시

수석 제품 디자이너, Flutter 아키텍트, 모바일 개발자, QA 엔지니어로서 실제 Android 기기에 설치·사용 가능한 완성 MVP를 개발한다.

필수 실행 원칙
1. Phase 0부터 마지막 Phase까지 순차 진행.
2. 각 Phase 구현 후 해당 단계 테스트 실행.
3. 실패한 테스트는 원인을 수정하고 재실행.
4. 테스트 실패를 무시하고 다음 단계로 넘어가지 않음.
5. Mock 화면이나 작동하지 않는 버튼을 완성 기능으로 보고하지 않음.
6. 작업 중간에 프로젝트 상태와 테스트 결과를 문서로 남김.
7. 사소한 구현 결정을 반복해서 묻지 않음.
8. 기존 코드가 있으면 먼저 검사하고 파괴적 변경을 피함.
9. 최종 APK를 실제로 빌드하고, 가능한 환경에서 설치·실행 검증.
10. 확인하지 않은 테스트·구동 결과를 성공으로 보고하지 않음.

외부 계정, 인증정보, 배포 서명키, 물리 기기가 필요한 상황에서는 임의로 만들거나 검증했다고 주장하지 않는다. 가능한 검증까지 수행하고 정확한 차단 사유를 기록한다.

최우선 가치: 디자인 품질 → 안정적인 독서 경험 → 데이터 신뢰성 → 기능 확장성.

## 1. 제품 비전

예수 그리스도를 중심으로 성경 전체의 흐름을 이해하도록 돕는 텍스트 기반 스토리 스터디 앱. 사용자는 먼저 이해하기 쉬운 해설형 이야기를 읽고, 그 후 실제 성경 본문과 연결한다.

신학적 중심: 창조와 타락 · 하나님의 언약 · 이스라엘의 역사 · 구속의 약속 · 예수 그리스도를 통한 성취 · 교회와 새 창조.

핵심 철학: 사용자가 앱에 의존하게 만들지 말고, 스스로 성경을 이해하도록 돕는다. 신앙적 부담, 성취 경쟁, 죄책감을 유발하는 UX를 사용하지 않는다.

## 2. MVP 범위

반드시 구현: 첫 실행 온보딩 · 이해 수준 선택(입문/성장/심화) · 하루 독서 시간(5/10/15/20분) · 매일 알림 시간 선택 및 비활성화 · 오늘의 스토리 홈 · 세로 스크롤 몰입형 읽기 · 독서 중단 지점 자동 저장·복원 · 성경 본문 위치 표시와 외부 성경 링크 · 오늘의 핵심 메시지 · 묵상 질문 3개와 개인 메모 · 읽기 완료 · 완료 기록 월간 캘린더 · 놓친 날 이어보기 · 같은 날 다음 스토리 추가 읽기 · 설정 변경 · 라이트/다크 모드 · 종료·재실행 후 데이터 보존 · 오프라인 본문 읽기.

콘텐츠: 7일 완결형 파일럿. 7개 챕터 모두 도입, 본문 맥락, 그리스도와의 연결, 실제 성경 참조, 묵상으로 구성된 완성 원고. 각 챕터는 5·10·15·20분 모드 지원. 30일 과정 전체의 제목·참조·교육 목표·순서는 별도 구조화 데이터. DAY 8–30은 읽을 수 있는 콘텐츠처럼 노출하지 않음. 7일 완결 후 자연스러운 완료 화면.

제외: 로그인/회원가입 · 서버·클라우드 동기화 · 광고·결제 · 실시간 AI 채팅 · 커뮤니티 · 리더보드 · 음성 낭독 · 교회 그룹 관리 · 소셜 피드 · 서버 CMS. 구현되지 않은 기능을 가짜 버튼이나 빈 화면으로 대체하지 않는다.

## 3. 기술 아키텍처

Flutter/Dart · Android 우선, iOS 확장 가능 구조 · Flutter stable, SDK 버전 기록 · targetSdk ≥ 36 · minSdk 26 · Material 3 기반 커스텀 디자인 시스템 · 로컬 SQLite · 버전 있는 JSON 콘텐츠 · Riverpod · go_router · flutter_local_notifications · timezone · shared_preferences · url_launcher. 라이브러리는 유지관리 상태·호환성·라이선스 확인 후 버전 고정. 불필요한 패키지, 웹뷰, 상태관리 중복 금지.

디렉터리: `lib/app/` · `lib/core/` · `lib/features/{onboarding,today,reader,journey,reflection,settings}/` · `lib/data/` · `assets/content/` · `assets/fonts/` · `test/` · `integration_test/` · `docs/`. 화면 위젯 안에 SQL이나 콘텐츠 파싱 로직을 넣지 않는다.

## 4. 디자인 디렉션 — Quiet Editorial Minimalism

조용한 서재, 잘 만든 문학책, 고급 출판물의 편집 디자인. 배경보다 텍스트, 장식보다 여백, 그래픽보다 타이포그래피. 20분 읽어도 피곤하지 않아야 한다.

금지: 과도한 카드형 UI · 큰 그림·배너 · 그라데이션 · 불필요한 그림자 · 장식적 십자가 패턴 · 과다 아이콘 · 게임 같은 업적 화면 · 강한 애니메이션 · 배경 이미지 · 과장된 CTA · 읽기 화면 상시 복잡한 내비게이션.

팔레트
- Light: Background `#F8F7F3` · Primary Text `#202722` · Secondary `#707770` · Accent `#365B4C` · Divider `#E5E6DF` · Surface `#FFFFFF`
- Dark: Background `#171D1A` · Primary Text `#ECEFE9` · Secondary `#A2ABA3` · Accent `#ADC5B5` · Divider `#343D36` · Surface `#202823`
- 기본 라이트, 시스템 연동과 수동 변경 지원.

타이포그래피: 본문·제목 Noto Serif KR, 내비게이션·설정·메타 Pretendard 또는 Noto Sans KR. 라이선스 확인 및 고지. 워드마크 24sp · 챕터 제목 27–30sp · 본문 17–18sp · 행간 1.7–1.85 · 소제목 19–21sp · 보조 12–14sp · 가로 여백 26px · 본문 최대 폭 약 560px. 양쪽 정렬 금지. 시스템 글자 크기 확대 존중.

화면: 홈(작은 워드마크, 날짜, 오늘의 제목, 한 줄 소개와 예상 시간, 단 하나의 주요 행동 `오늘의 이야기 읽기`, 절제된 진행 텍스트) · 읽기(뒤로가기, DAY 번호, 얇은 진행 표시, 스크롤 중 UI 숨김, 서체로 강조, 마지막에만 `오늘의 이야기 완료하기`) · 여정(월간 달력, 작은 완료 마크, 미완료를 실패처럼 표현하지 않음, 하루 여러 챕터 정확히 반영) · 설정(난도·시간·알림·테마 목록).

인터랙션: 짧고 부드러운 전환 · 바운스 금지 · 터치 영역 44–48dp 이상 · 재개 시 위치 복원 · 애니메이션 감소 설정 존중 · 키보드가 묵상 입력을 가리지 않음.

## 5. 콘텐츠 엔진

챕터 데이터: ID · 시즌 ID · 순서 · 제목/부제 · 성경 참조 범위 · 학습 목표 · 신학 주제 · 도입 서사 · 역사·문학 맥락 · 언약의 연결 · 그리스도와의 연결 · 심화 해설 · 핵심 한 문장 · 묵상 질문 3개 · 외부 본문 링크 · 콘텐츠 버전 · 편집 검수 상태.

읽기 시간: 잘라내지 않고 확장 모듈 추가. 5분(핵심 이야기, 언약·그리스도 연결, 본문 참조) · 10분(+서사·맥락) · 15분(+역사·문학 배경) · 20분(+관련 본문 비교, 심화). 모든 모드에서 자연스러운 시작과 결말. 시간은 목표값.

수준: 입문(인물·지명·용어 풀이) · 성장(언약, 구속사, 구약·신약 연결) · 심화(본문 구조, 신학적 해석). 같은 이야기, 설명 레이어 깊이만 조절.

신학 원칙: 정통 기독교 핵심 신앙 · 원래 문맥 존중 · 무리한 예표 금지 · 신약의 명시적 해석과 해설자 추론 구분 · 본문에 없는 대화·행동을 사실처럼 창작 금지 · 교단 간 차이 단정 금지 · 참조 검증 · AI 초안을 감수 완료로 표시 금지. 상태: Draft / Technical QA Passed / Theology Review Pending / Approved.

저작권: 현대 한국어 번역문 긴 인용·전문 금지. 독립 해설 원고. 참조 위치와 외부 링크로 연결. 스크래핑 금지. 법적 조건 미확인 짧은 인용도 기본 제외.

## 6. MVP 콘텐츠 목록

- DAY 01 세상은 왜 창조되었을까? — 창 1–2, 요 1:1–5
- DAY 02 인간은 왜 하나님을 떠났을까? — 창 3, 롬 5:12–19
- DAY 03 하나님은 실패한 인간을 포기하셨을까? — 창 3:14–21 (3:15의 해석적 성격 명시)
- DAY 04 가인은 왜 동생을 죽였을까? — 창 4
- DAY 05 홍수 속에도 은혜가 있었을까? — 창 6–9, 노아 언약
- DAY 06 사람들은 왜 바벨탑을 세웠을까? — 창 11:1–9 (행 2는 주제적 비교, 예언 성취로 단정 금지)
- DAY 07 하나님은 왜 아브라함 한 사람을 부르셨을까? — 창 11:27–12:9, 갈 3:6–16
  흐름: 하나님은 인간을 포기하신 걸까요? → 특별해 보이지 않는 한 사람 → 바벨탑의 사람들과 아브라함 → 큰 민족에 대한 약속과 현실의 긴장 → 이 이야기는 왜 예수님과 연결될까요? → 오늘 우리에게 남는 이야기 → 실제 성경 본문 연결 → 묵상 질문
- DAY 08–30 커리큘럼 개요 JSON (본문 없는 항목은 완성으로 처리 금지)

## 7. 상태 저장 및 스케줄 로직

데이터: UserSettings · ChapterMetadata · ReadingProgress · CompletionRecord · ReflectionNote · ReminderPreference.

규칙: 진도는 chapter ID 기준 · 완료일은 현지 시간대 · 완료 챕터와 달력 완료일은 별도 개념 · 하루 두 챕터 완료 가능 · 재독해도 원래 완료 기록 유지 · 연속 기록 계산으로 기록 삭제 금지 · 재실행 후 유지 · 시스템 날짜/시간대 변경에도 기록 유지 · 마이그레이션 고려한 스키마 버전.

완료: 스크롤로 자동 완료 금지, 마지막 `완료하기` 버튼으로만. 메모는 선택.

놓친 날: 벌점·경고 없음. 마지막 미완료 챕터를 자연스럽게 이어 읽기. "연속 기록이 끊어졌습니다" 같은 문구 금지.

알림: 시각 설정, 시간대 기반 로컬 알림, Android 13+ 권한 명시 요청, Exact Alarm 강요 금지(비정확 예약), 끄면 예약 취소, 시각 변경·재부팅·업데이트·시간대 변경 시 재예약 검증, 그날 완료 시 남은 알림 취소(가능하면), 탭하면 오늘/다음 스토리로 이동, 권한 거부에도 나머지 정상 작동.

## 8. Phase 및 검증 게이트

- PHASE 0 환경 조사·프로젝트 준비 — `flutter doctor -v`, `flutter pub get`, 최소 앱 `flutter build apk --debug`, 차단 사항 기록
- PHASE 1 디자인 시스템 — 토큰, 라이트/다크, 워드마크·아이콘, 공통 스타일, 화면 골격, 360px·태블릿 대응, 스크린샷 점검
- PHASE 2 코어 앱 — 온보딩, 라우팅, 홈, 독서, 설정, 로컬 DB, 로더, 위치 저장, 메모 저장
- PHASE 3 콘텐츠·학습 엔진 — 7개 원고, JSON 검증, 시간 모드, 수준 설명, 질문, 핵심 메시지, 30일 개요, 신학·출처 검증 기록
- PHASE 4 여정·알림 — 캘린더, 완료 기록, 재독, 추가 읽기, 놓친 날, 로컬 알림, 권한 거부, 날짜·시간대 테스트
- PHASE 5 집중 QA·디자인 개선 — 전체 흐름 자동 테스트, 접근성·폰트 확대, 테마, 소형 화면, 영속성, 스크롤 성능, 콘텐츠 구조, 크래시·오버플로, 스크린샷 점검. `flutter analyze` 무오류, 전체 테스트 통과, P0/P1 결함 없음
- PHASE 6 최종 빌드·배포 준비 — 정리, README, 전체 재테스트, Release APK, 기기 설치·실행, 크기·SHA-256, 스크린샷, 최종 보고. 기기가 없으면 "기기 구동 검증 미완료" 명시. 정식 서명키 없이 출시 준비 완료라 주장 금지.

## 13. 최종 품질 기준

잘 디자인된 한 권의 책을 펼친 느낌. 모든 글자와 여백에 이유가 있다. 기능을 배우지 않고 바로 읽는다. 쉬워야 하지만 가볍지 않다. 아름답지만 내용보다 눈에 띄지 않는다. 기능이 많기보다 필요한 기능이 완성도 있게 작동한다.
성공 기준: 매일 다시 펼치고 싶은 독서 경험 · 그리스도 중심으로 성경을 깊이 이해하게 하는 콘텐츠 · 테스트를 통과하고 실제 기기에서 안정적으로 실행되는 앱.
