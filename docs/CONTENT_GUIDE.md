# FOCUS JESUS — 콘텐츠 작성 가이드 (Season 1 · v1.0)

이 문서는 모든 챕터 원고가 같은 목소리, 같은 신학 원칙, 같은 구조를 갖도록 하는 기준입니다.
원고는 `assets/content/season1/dayNN.json` 에 저장하고, 반드시 아래 명령으로 검증합니다.

```
source /opt/sdk/env.sh   # (개발 환경에서만)
dart run tool/validate_content.dart assets/content/season1/dayNN.json
```

검증기가 `OK` 를 출력할 때까지 수정합니다. 검증기 규칙은 `lib/data/content/content_validator.dart` 에 있습니다.

---

## 1. 목소리와 문체

- **누구에게**: 성경을 잘 모르는 성인부터 오래 믿어 온 성도까지. 쉬워야 하지만 가볍지 않게.
- **문체**: 본문은 부드러운 격식체(`~합니다`, `~입니다`). 소제목은 질문형(`~일까요?`)이나 짧은 명사구.
  같은 챕터 안에서 반말·해요체를 섞지 않습니다.
- **리듬**: 한 문단은 3–6문장, 공백 제외 120–450자 정도. 한 문단에 하나의 생각만 담습니다.
- **잘 만든 책처럼**: 설교나 광고 문구처럼 쓰지 않습니다. 느낌표, 과장된 형용사, “놀랍게도!” 같은 감탄 표현은 피합니다.
- **독자를 존중**: 죄책감, 의무감, 성취 압박을 주지 않습니다. (“매일 읽지 않으면…” 같은 표현 금지)
- **강조 문장(emphasis)**: 챕터마다 1–3개. 한 문장, 공백 제외 140자 이하. 서체로만 강조하므로 내용이 스스로 무게를 가져야 합니다.

## 2. 신학 원칙 (필수)

1. 정통 기독교의 핵심 신앙(삼위일체, 창조, 타락, 은혜에 의한 구원, 그리스도의 죽음과 부활, 새 창조)에 근거합니다.
2. **원래 문맥을 먼저** 설명합니다. 그 이야기가 처음 들려졌을 때 무엇을 말했는지가 먼저입니다.
3. 모든 구절에 무리하게 예수님의 예표를 넣지 않습니다.
4. **명시적 해석과 추론을 구분합니다.**
   - 신약이 직접 연결하는 경우: “신약성경은 이 장면을 직접 이렇게 해석합니다(갈라디아서 3:16).”
   - 교회의 전통적 해석인 경우: “초대 교회 이후 많은 그리스도인은 이 구절을 ~로 읽어 왔습니다.”
   - 해설자의 추론인 경우: “이것은 본문이 직접 말하는 내용이라기보다, 성경 전체의 흐름에서 읽어 본 해석입니다.”
5. 본문에 없는 대화·행동·감정을 **사실처럼** 쓰지 않습니다. 상상을 돕고 싶다면 “상상해 보면” 처럼 상상임을 밝힙니다.
6. 교단 간 해석이 갈리는 문제(창조의 ‘날’의 길이, 홍수의 범위, 세례의 의미 등)는 단정하지 않고 “여러 해석이 있다”고 공정하게 소개합니다.
7. 성경 책 이름과 장절은 정확해야 합니다(검증기가 실제 장·절 수로 확인합니다).
8. 이 원고는 AI가 작성을 도운 초안입니다. `reviewStatus` 는 항상 `"theologyReviewPending"` 으로 둡니다. `approved` 는 사람 신학 검수자만 설정합니다.

## 3. 저작권 (필수)

- 개역개정, 새번역, 쉬운성경 등 **현대 한국어 성경 번역문을 인용하지 않습니다.** 짧은 구절도 그대로 옮기지 않습니다.
- 본문 내용은 **자신의 말로 풀어 쓰기(paraphrase)** 합니다. 예: “하나님은 아브람에게 고향과 친척과 아버지의 집을 떠나 하나님이 보여 줄 땅으로 가라고 말씀하십니다.”
- 따옴표 안의 내용은 공백 제외 50자를 넘지 않게 합니다(검증기가 검사합니다). 따옴표 안이라도 번역문을 옮기지 말고 요약하세요.
- 실제 본문은 `scripture` 블록과 `references` 로 위치만 안내하고, 앱은 외부 성경 사이트로 연결합니다.
- 외부 해설서·웹사이트의 문장을 옮기지 않습니다.

## 4. JSON 구조

```json
{
  "schemaVersion": 1,
  "id": "s1-d07",
  "seasonId": "s1",
  "order": 7,
  "title": "하나님은 왜 아브라함 한 사람을 부르셨을까?",
  "subtitle": "바벨의 흩어짐 이후, 한 사람에게서 다시 시작된 약속",
  "summary": "홈 화면에 보일 한 줄 소개 (70자 이하)",
  "contentVersion": "1.0.0",
  "reviewStatus": "theologyReviewPending",
  "references": [
    { "ref": "GEN 11:27-12:9", "role": "primary" },
    { "ref": "GAL 3:6-16", "role": "related" }
  ],
  "learningObjectives": ["학습 목표 2–4개"],
  "themes": ["부르심", "언약", "모든 민족"],
  "keyMessage": "오늘의 핵심 한 문장 (120자 이하)",
  "sections": [
    {
      "id": "d07-s01",
      "tier": 5,
      "kind": "opening",
      "heading": "하나님은 인간을 포기하신 걸까요?",
      "blocks": [
        { "type": "paragraph", "text": "…" },
        { "type": "emphasis", "text": "…" },
        { "type": "scripture", "ref": "GEN 12:1-3", "text": "창세기 12장 1–3절을 천천히 읽어 보세요. 약속의 말씀이 세 번 반복되는 ‘복’이라는 단어를 따라가 보면 좋습니다." }
      ],
      "levelNotes": {
        "beginner": ["어려운 인물·지명·용어를 친절하게 풀어 주는 짧은 설명"],
        "growth": ["언약·구속사·구약과 신약의 연결을 짚는 설명"],
        "deep": ["본문 구조, 원어의 뉘앙스, 주요 해석의 차이를 다루는 설명"]
      }
    }
  ],
  "reflectionQuestions": ["질문 1?", "질문 2?", "질문 3?"]
}
```

### 참조 표기 (`ref`)
`GEN 3` (장 전체) · `GEN 6-9` (여러 장) · `GEN 12:1-3` · `GEN 3:15` · `GEN 11:27-12:9`
책 코드는 USFM 대문자 코드입니다: GEN EXO LEV NUM DEU … MAT MRK LUK JHN ACT ROM 1CO 2CO GAL EPH PHP COL 1TH 2TH 1TI 2TI TIT PHM HEB JAS 1PE 2PE 1JN 2JN 3JN JUD REV.

### section `kind`
`opening`(여는 질문) · `story`(성경 이야기 다시 들려주기) · `context`(서사와 문학적 맥락) · `history`(역사·문화 배경) ·
`covenant`(언약의 연결) · `christ`(예수 그리스도와의 연결) · `comparison`(관련 본문 비교) · `deep`(심화 해설) · `today`(오늘 우리에게 남는 이야기)

### section `tier` — 읽기 시간 모드
섹션은 **읽는 순서대로** 배열하고, 각 섹션에 그 섹션이 처음 포함되는 가장 짧은 모드를 지정합니다.
- 5분 모드: tier 5 섹션만
- 10분 모드: tier 5 + 10
- 15분 모드: tier 5 + 10 + 15
- 20분 모드: 전부

모든 모드에서 이야기가 자연스럽게 시작하고 끝나야 하므로 다음 규칙을 지킵니다.
- 첫 섹션은 `opening`(tier 5), 마지막 섹션은 `today`(tier 5).
- `story` 와 `christ` 섹션이 tier 5 에 최소 하나씩 있어야 합니다. 5분 모드의 christ 섹션에는 **언약의 연결과 그리스도의 연결**이 함께 들어갑니다.
- tier 5 섹션 안에 `scripture` 블록이 최소 1개 있어야 합니다.
- tier 10/15/20 섹션은 **앞뒤 tier 5 섹션 사이에 끼워 넣어도 흐름이 끊기지 않게** 씁니다.
  확장 섹션이 빠져도 tier 5 섹션끼리 자연스럽게 이어져야 하고, 확장 섹션이 들어와도 중복 설명이 없어야 합니다.
  (확장 섹션에서 “앞에서 말했듯이” 처럼 빠질 수 있는 섹션을 가리키지 마세요.)

권장 배치(예시):

| 순서 | kind | tier | 공백 제외 분량 |
|---|---|---|---|
| 1 | opening | 5 | 300–400 |
| 2 | story | 5 | 800–1,000 |
| 3 | context (서사 확장) | 10 | 1,000–1,200 |
| 4 | story 또는 context (서사 확장 2) | 10 | 900–1,100 |
| 5 | history (역사·문학 배경) | 15 | 1,000–1,200 |
| 6 | covenant 또는 context | 15 | 900–1,100 |
| 7 | christ (핵심 연결) | 5 | 600–800 |
| 8 | comparison (관련 본문 비교) | 20 | 1,000–1,200 |
| 9 | deep (심화 설명) | 20 | 1,000–1,200 |
| 10 | today | 5 | 300–400 |

정확한 배치는 이야기에 맞게 조정해도 됩니다. 단, 아래 분량 기준은 반드시 지킵니다.

### 분량 기준 (검증기가 강제)
읽기 속도는 **공백 제외 500자/분**으로 추정합니다. 제목·문단·곁 설명·핵심 문장·묵상 질문이 모두 포함됩니다.

| 모드 | 목표 | 허용 범위 (모든 수준에서) |
|---|---|---|
| 5분 | ≈ 2,500자 | 3.5–6.75분 (1,750–3,375자) |
| 10분 | ≈ 5,000자 | 7–13.5분 |
| 15분 | ≈ 7,500자 | 10.5–20.25분 |
| 20분 | ≈ 10,000자 | 14–27분 |

- 긴 모드는 짧은 모드보다 최소 1,500자 이상 많아야 합니다.
- 실전 목표: tier 5 본문 ≈ 2,000자, tier 10 추가 ≈ 2,200자, tier 15 추가 ≈ 2,200자, tier 20 추가 ≈ 2,200자.
- 심화(deep) 수준은 growth + deep 노트를 모두 보여 주므로 노트가 너무 길면 5분 모드가 범위를 넘습니다. 검증 출력을 보며 조정하세요.

### 수준별 곁 설명 (`levelNotes`)
수준은 **이야기를 바꾸지 않고 설명의 깊이만** 바꿉니다.
- 입문(`beginner`) 노트만 입문 수준에서 보입니다: 인물·지명·용어 풀이, 배경 상식. 친절하고 짧게(공백 제외 80–200자).
- 성장(`growth`) 노트는 성장·심화 수준에서 보입니다: 언약의 흐름, 구약과 신약의 연결.
- 심화(`deep`) 노트는 심화 수준에서만 보입니다: 문학 구조, 히브리어·헬라어 단어의 뉘앙스(음역 표기, 원문 글자 없이), 해석사의 주요 견해.
- 각 수준마다 **tier 5 섹션에 최소 1개**, 챕터 전체에 **4–8개** 노트를 둡니다.
- 노트는 앞뒤 문단을 반복하지 않고 그 자리에서 필요한 설명만 더합니다.

### 묵상 질문
정확히 3개, 모두 `?` 로 끝납니다. 정답을 요구하지 않고, 본문을 다시 들여다보게 하고, 삶과 연결하되 죄책감을 주지 않는 질문.
권장 흐름: (1) 본문 관찰 → (2) 그리스도와의 연결 → (3) 오늘의 삶.

## 5. 금지 사항
- 더미 문장, “추후 작성”, 같은 문단 반복, 의미 없는 채움말.
- 번역문 인용(3장 참고).
- 확인되지 않은 역사적·과학적 단정(“고고학이 증명했다” 등).
- 다른 종교·교단 폄하.
- 독자의 신앙 상태를 판단하거나 압박하는 문장.
